# Android drawing app review — 29 October 2026

> Follow-up: [Brush Atelier implementation](BRUSH_ATELIER.md) records newer brush,
> eraser, sibling-transform and motion improvements, with updated verification.

## Assessment

The app has a useful foundation: local coordinate frames for deep zoom, vector strokes, pressure brushes, layers, selections, image placement, bookmarks and offline persistence. This pass fixes substantial correctness, reliability, input and export problems and installs the result on the Galaxy Tab S9 FE. It does **not** establish release readiness or full feature parity with a commercial drawing application.

The repository describes Infinitefy's ZoomArt as its reference. The request also names “iOS infinity design”; Infinite Design is a different Android product. This review therefore targets the infinite-zoom drawing experience, with vector-editing features considered separately. No competing application's implementation or artwork was copied.

Existing uncommitted brush-preview, color-wheel, icon and style work was preserved. Changes and verification below describe this review pass, rather than claiming authorship of that earlier work.

## Changes implemented

### Drawing, selection and rendering

- Render layers in their actual stacking order, including images, shapes, strokes and live ink. Previously, type/level ordering could put lower-layer content above upper-layer strokes.
- Composite layer opacity once over the assembled layer rather than repeatedly over overlapping marks.
- Retain document stroke order after spatial-index lookup; grid traversal order is not paint order.
- Reindex transformed strokes immediately; prune stale or locked selections after history/layer changes; include shapes in pruning.
- Preserve image mirroring in transforms, duplication, undo and document serialization. Implement vertical flipping consistently.
- Do not create history entries for unchanged transforms, preserving redo after a selection tap.
- Prevent spatial-index span overflow at extreme coordinates, include brush/scatter padding in indexed bounds and discard empty buckets.
- Cache unchanged ordinary stroke outlines with an estimated 8 MiB budget and explicit geometry revision invalidation. Bound decoded images with a 32 MiB LRU cache.
- Use rotated clip bounds for scene visibility and omit bookmark annotations from clean export rendering.

### Input and navigation

- Track the actual stylus pointer ID, including historical samples, when a finger touches first.
- Correct selection rotation units and convert selection/pan/fling movement through the rotated canvas frame.
- Add optional finger drawing, disabled by default. A second finger transitions to navigation and cancels uncommitted ink; live destructive edits retain their undo transaction.
- Restrict pen-hold pin creation to drawing and avoid creating a pin on cancellation.
- Cancel bookmark flight animation on touch or a new flight; stop animations/flings and release view caches on detachment.

### Saving and recovery

- Use AtomicFile for the normal session. A failed write no longer first removes the previous good file.
- Make recovery durable before deleting the recovery source. Preserve unreadable sessions for investigation rather than silently overwriting the only copy.
- Archive the current session before starting a new project; require confirmation in the title UI. Activity recreation with the original New intent no longer clears the resumed drawing.
- Honor the configured autosave interval, including Off, and save on pause.
- Avoid stacking crash handlers that could save an obsolete Activity's document over the latest one; replace crash snapshots atomically where supported.
- Persist brush angle, dashes, scatter, spacing and erase state, plus mirrored-image state.
- Support JSON Unicode/control-character escapes; reject trailing data, non-finite numeric values, invalid camera scale and unsupported future document versions.

### Import and export

- Decode and normalize imported photos off the UI thread, bound decode resolution and respect EXIF orientation. Avoid leaking decoded bitmaps after import.
- Offer PNG export of either the current rotated view or the entire drawing.
- Fit whole-drawing bounds in the nearest shared zoom frame instead of relying on root-coordinate precision. Include descendant levels during whole-drawing export; account for rotated images and smudge bounds.
- Create a detached document snapshot for background export so rendering does not race with live geometry/Paint mutations.
- Replace the MP4 input path with stride-aware YUV420 input images, continuous encoder draining, deterministic timestamps, end-of-stream checks and partial-file cleanup.
- Publish gallery files through pending MediaStore entries, remove unsuccessful entries and check PNG compression results.
- Offer Android's share chooser through a narrowly scoped FileProvider for exported files.

### Interface and verification

- Put Undo/Redo near the main drawing tools; add icon tooltips and selected state; switching to a brush returns to drawing mode.
- Wire the dock-orientation preference into actual layout, make Settings scrollable and repair the floating-panel handle/content overlap.
- Restore hidden controls when auto-hide is disabled; avoid rebuilding panels that are not visible.
- Add the vibration permission and correct the MP4 output-format constant, removing the five baseline lint errors.
- Add regression tests, an on-device smoke suite and a GitHub Actions build/test/lint workflow. The workflow has not been run remotely during this review.

## Remaining priorities

These are concrete follow-up requirements, not features completed by this patch. P0 means resolve before trusting important artwork or claiming unlimited navigation; P1 means resolve before public release; P2 improves competitiveness.

| Priority | Area and evidence | Required improvement / acceptance criterion |
|---|---|---|
| P0 | `Camera.transformTo`, `ZoomLevel`, bookmark flight math: ancestor/descendant transforms are assumed; root-space Double math still appears in flights. Interactive visibility intentionally remains ancestors plus immediate children. | Implement common-ancestor transforms and local-space bookmark interpolation. Test sibling branches, repeated deep round trips and pinch focus continuity at hundreds of levels without disappearance, exceptions or drift. The depth-180 PNG test is not proof of every navigation path. |
| P0 | `MainActivity.saveSession`: serialization and storage still run on the UI thread; crash snapshots are best-effort. | Introduce immutable document snapshots and an ordered background save queue with revisions, cancellation/coalescing and last-good checkpoints. Kill the process at each save stage, simulate disk full and restore exact geometry/assets. |
| P0 | `StrokeEraser`: checks sample points against eraser centers rather than clipping intersecting segments. | Clip variable-width stroke geometry against swept eraser capsules, interpolate new endpoints/pressure and preserve taper/level metadata. Sparse two-point strokes crossed at their midpoint must erase; no-hit erasing must avoid replacing strokes. |
| P1 | Single-session storage and hidden `project_backups` directory. | Add a project library with thumbnails, rename/duplicate/delete/restore, portable project archives containing image assets, migrations and explicit save/error state. Backups must be discoverable and recoverable in the UI. |
| P1 | `DocumentCodec`: bespoke permissive parser and partial field validation. | Enforce document-size/count/depth bounds, graph validity, unique IDs, finite coordinates and brush limits; add schema fixtures and corruption/fuzz tests. Reject cyclic or excessive level graphs before rendering. |
| P1 | `ZoomableCanvasView` mixes input, rendering, gesture state, animation and bitmap work. | Extract a document renderer, input state machine and navigation controller. Share an immutable render representation with export; keep Android View lifetime separate from document lifetime. |
| P1 | Live-stroke outlines, special brushes, smudges and large scenes remain expensive. Ordinary path cache accounting is estimated. | Measure with Perfetto/FrameMetrics on real canvas gestures; cache special-brush geometry, process only changed eraser regions, use level-of-detail simplification and benchmark long sessions. Establish 16.7 ms p95 screen-frame and bounded-memory targets on the tablet, then verify rather than infer them from the software probe. |
| P1 | Unbounded undo/history and publicly mutable geometry collections. | Add memory-aware history limits/checkpoints and mutation APIs that enforce index/cache revision updates. Stress thousands of transforms, undo/redo and project loads without runaway memory or stale geometry. |
| P1 | Gesture cancellation, final pen sample and physical hardware behavior need broader coverage. | Define cancel/commit semantics per tool; test pen side button/eraser, pressure curve calibration, hover, palm contact during every gesture, rotation/pinch focus, system interruption and stylus-only mode with a real S Pen. |
| P1 | Dock is still a long icon strip; brush sliders are small; floating panels can obscure controls or overflow narrow windows. | Use a compact primary tool rail plus contextual controls and a secondary overflow menu. Provide 48 dp touch targets, visible values, named brush settings, scrollable panels, safe inset placement and left/right-handed layouts. Test phone, tablet, split-screen, DeX and large font sizes. |
| P1 | Accessibility and localization are incomplete; many labels are hard-coded. | Move copy into resources; expose slider names/ranges and tool state to TalkBack; verify contrast, focus order, keyboard shortcuts, reduced animation and system haptic preferences. Avoid color-only tool selection. |
| P1 | Import worker and snapshot export improve responsiveness but are still Activity-owned; video conversion is CPU-heavy. | Add cancellable jobs with progress/error feedback and lifecycle ownership. Verify large rotated photos, transparent images, decode failures, backgrounding, storage failure and repeated exports. Benchmark video duration/resolution and investigate a surface encoder after profiling. |
| P1 | PNG is bounded raster output, and video tours still need deep-navigation/framing validation. | Add explicit output size/background/crop controls, tour preview and keyframe timing. Verify canvas/export visual parity for every brush, blend mode, mirrored image and deep bookmark transition. Consider SVG only after defining representable features and fallbacks. |
| P1 | `compileSdk`/`targetSdk` remain 34; package is `com.example.zoomart`; release pipeline is not established. | Migrate to current Play requirements with edge-to-edge/inset and permission regression tests, choose final application identity, configure release signing outside source control, test optimized release builds and review privacy/data-backup behavior. Verify current policy before submission. |
| P1 | 67 lint warnings remain, and new CI is unexecuted remotely. | Triage warnings by correctness/accessibility before cosmetic cleanup. Run CI on a clean checkout and add a device/emulator matrix including API 26 and the current release. Keep performance thresholds separate from flaky functional tests. |
| P2 | Artist workflow lacks a cohesive library of reusable presets and navigation aids. | Add user brush presets, recent/favorite colors, numeric color entry, quick size/opacity controls, bookmark thumbnails, fit/reset rotation and a discoverable gesture guide. Validate with drawing sessions, not screenshots alone. |
| P2 | Professional vector-editing parity is much broader than infinite zoom. | Scope node/path editing, snapping/guides, symmetry, Boolean operations, text and advanced masks as explicit milestones. Do not advertise these based on existing basic shape tools. |

## Suggested release gates

1. **Trust the document:** recoverable project library, transactional background saving, schema validation, asset archive import/export and process-death tests.
2. **Trust the canvas:** common-ancestor precision, segment-aware erasing, deterministic history, complete gesture cancellation and real S Pen validation.
3. **Trust performance:** screen-frame traces for 1k/10k/100k strokes, dense single strokes, 50 layers and imported images; memory plateau after 30 minutes; measured export progress/cancellation.
4. **Trust the interface:** tablet/phone layouts, reachable controls in split-screen, TalkBack traversal and an artist completing create/draw/zoom/bookmark/save/reopen/share without instruction.
5. **Trust distribution:** current target SDK, release signing, optimized-build tests, current device coverage, clean CI and accurate store claims.
